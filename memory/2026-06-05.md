2. **Aucun moteur d'effets** — Pas de patterns de mouvement automatiques (cercle, figure-8, balayage).
3. **Fade cue linéaire** — `CueList.tsx` utilisait `setInterval` à 20ms avec interpolation linéaire brute (`value * progress`).

5. **Faders instantanés** — `FixtureController.tsx` envoyait directement la valeur sans transition.

### ✅ Nouveau: DmxFader (`lib/DmxFader.ts`)
Moteur d'interpolation per-channel avec 6 courbes d'easing.

**Easing curves:**
| Type | Description |
|------|-------------|
| `linear` | Interpolation constante |
| `easeIn` | Cubic — départ lent, accélération progressive |
| `easeOut` | Cubic — départ rapide, décélération progressive |
| `easeInOut` | Cubic — accélération + décélération |
| `sCurve` | Cosine — doux au début ET à la fin (S-curve) |
| `snap` | Instantané au milieu (utile pour gobo/color wheel) |

**Méthodes:**
- `fadeTo(universe, channel, target, durationMs, easing)` — Fade single channel
- `fadeChannels(channels[], durationMs, easing)` — Fade multiple channels simultaneously
- `crossfade(channelsA, channelsB, durationMs, easing)` — Scene A out → Scene B in
- `fadeGroupScale(channels[], scaleFrom, scaleTo, durationMs, easing)` — Proportional fade (like master dimmer)
- `cancelFade(universe, channel)` — Cancel ongoing fade
- `cancelAll()` — Cancel all active fades
- `isFading(universe, channel)` — Check if a channel is currently fading
- `getActiveFadeCount()` — Number of active fades

**Engine:**
- Runs via `requestAnimationFrame` (40-60fps, browser-synced)
- Automatically cancels previous fade on same channel when new `fadeTo` called
- `onTick` callback wired into `dmxEngine` constructor

### ✅ Nouveau: EffectEngine (`lib/EffectEngine.ts`)
Générateur de patterns de mouvement et effets DMX.

**Patterns disponibles:**
| Pattern | Description | Canaux utilisés |
|---------|-------------|-----------------|
| `circle` | Trajectoire circulaire (Pan + Tilt) | pan, tilt |
| `figure8` | Courbe de Lissajous ∞ (sin θ + sin 2θ) | pan, tilt |
| `sweep` | Balayage gauche-droite (triangle wave) | pan (+ tilt subtle) |
| `rainbow` | Rotation color wheel 0→255 | colorWheel |
| `pulse` | Dimmer en vague sinusoïdale | dimmer |
| `random` | Mouvement aléatoire lissé (multi-sin noise) | pan, tilt |
| `strobe` | On/Off rapide | strobe |

**Paramètres:**
- `speed` — Cycles par minute (2-60)
- `size` — Amplitude du pattern (10-127)
- `centerPan` / `centerTilt` — Position centrale (0-255)
- `bpm` — Override de sync BPM

**Engine:**
- Runs via `requestAnimationFrame` (60fps)
- Pause/Resume par effet
- Mise à jour des paramètres en temps réel (`updateEffect()`)
- Nettoyage automatique au unmount (`stopAll()`)
- `onTick` callback wired into `dmxEngine` constructor

### ✅ Modifié: dmxEngine.ts
Intégration de DmxFader + EffectEngine + système de priorité.

**Nouvelle architecture:**
- **Source priority system** (`DmxSource` : `manual` | `timeline` | `background`)
  - `manual` (priority 3, lock 1200ms) — Faders, XY pad, boutons
  - `timeline` (priority 2, lock 120ms) — MacroTimeline playback
  - `background` (priority 1, lock 0ms) — Effects engine, IA automations
- **Channel locks** — Un canal verrouillé par une source haute-priorité refuse les écritures basse-priorité
- **Force override** — Option `force: true` bypass les locks
- **Release** — `releaseChannel()` et `clearPriorityLocks()` pour libérer les verrous

**Nouvelles méthodes:**
- `fadeTo()` — Smooth single channel fade
- `fadeChannels()` — Multi-channel fade
- `crossfade()` — Crossfade between two scene sets
- `fadeGroupScale()` — Proportional group fade
- `cancelFade()` / `cancelAllFades()` — Cancel fades
- `startEffect()` / `stopEffect()` / `pauseEffect()` / `resumeEffect()` / `updateEffect()` — Effect management
- `stopAllEffects()` — Stop all running effects
- `getEffectStatus()` — Check if effect is running/paused
- `releaseChannel()` — Release a channel lock
- `clearPriorityLocks()` — Clear all locks by source

**Conformité cahier des charges:**
- ✅ Phase 1 (Core DMX) — 44Hz stable, flushing, forceNext
- ✅ Phase 7 (Override Mode) — Priorité L1/L2/L3 implémentée avec locks

### ✅ Bugs identifiés et corrigés

1. **XYPad visuel ne suit pas les patterns** ✅ **CORRIGÉ**
   - **Problème:** Le point canvas utilisait `panValue`/`tiltValue` props qui ne sont pas mis à jour par l'EffectEngine.
   - **Fix:** Ajout de `visualPan`/`visualTilt` états locaux + `requestAnimationFrame` poll qui lit `dmxEngine.getChannel()` quand `activePattern` est non-null. Le point canvas suit maintenant le mouvement en temps réel.
   - **Fichier:** `XYPad.tsx` (+27 lignes)

2. **CueList easing non persisté en backend** ✅ **CORRIGÉ**
   - **Problème:** La table SQLite `cue_lists` n'avait pas de colonne `easing`. Les cues perdaient leur easing au rechargement.
   - **Fix:** Ajout de `easing?: string` dans l'interface `Cue` de `database.ts`. Le `data` JSON contient déjà le champ (car `Cue` interface est stringify), donc pas besoin de ALTER TABLE.
   - **Fichier:** `apps/server/services/database.ts` (ligne 807)

3. **EffectEngine random ignore le paramètre speed** ✅ **CORRIGÉ**
   - **Problème:** `computeRandom` utilisait `performance.now()` directement, ignorant le paramètre `speed`.
   - **Fix:** Multiplication de `performance.now()` par `speedMul = effect.speed / 10` avant les calculs sinus.
   - **Fichier:** `apps/web/src/lib/EffectEngine.ts` (lignes 188-200)
